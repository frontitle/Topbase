# Topbase 0.2.1

发布日期：2026-08-30

0.2.1 建立 Topbase 的首个正式版本基线，覆盖核心分析流程、应用数据库持久化、升级迁移、Docker 部署与 AI 开发者入口。

## 升级前必须确认

1. 备份当前应用数据库或完整 SQLite 数据目录。
2. 单独备份并确认当前 `TOPBASE_MASTER_KEY`；丢失后无法恢复加密的数据源连接。
3. 记录当前 Git commit、启动环境变量和反向代理配置。
4. SQLite Docker 部署必须确认 `/data` 已持久化，禁止执行 `docker compose down -v`。

## 数据库变化

- 应用数据库 Schema 版本升级到 14。
- 新增迁移记录、安装身份、加密连接秘密、分布式租约、仪表盘嵌入控制、数据表可见性、表级业务说明和 API Key 有效期。
- 启动时自动按顺序执行缺失 migration，并校验所有已执行 migration 的 SHA-256。
- migration 只向前执行。数据库升级后如需回滚，必须同时恢复升级前备份，不能只替换旧二进制。

## 从源码升级

```bash
git fetch --tags
git checkout v0.2.1
make check
make build
```

停止旧进程，保留原环境变量和主密钥，替换 `bin/topbase` 后重新启动。确认：

```bash
curl --fail http://localhost:8080/api/ready
curl --fail http://localhost:8080/api/version
```

`/api/version` 应返回 `version: 0.2.1` 和 `schema_version: 14`。

## Docker 升级

使用发布镜像：

```bash
export TOPBASE_VERSION=0.2.1
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

从源码构建镜像时使用：

```bash
git checkout v0.2.1
docker compose -f docker-compose.postgres.yml build --pull
docker compose -f docker-compose.postgres.yml up -d
```

命名卷不会因 `up -d` 被删除。不要使用 `down -v`。

## 升级后的行为变化

- 开发者模式默认关闭。管理员需要在“管理后台 → 设置 → 开发者模式”中重新确认外部 API 策略。
- 旧 API Key 不会被删除；启用开发者模式后，尚未过期且未撤销的 Key 可以继续使用。
- SQLite 仍可用于开发体验，但正式运行建议在后台迁移到 PostgreSQL 或 MySQL。
- 多节点必须连接同一个应用数据库，并使用完全相同的 `TOPBASE_MASTER_KEY` 和不同的 `TOPBASE_INSTANCE_ID`。

## 验收清单

- 管理员可以登录，用户、数据源连接、分析和仪表盘仍存在；
- 数据源可以重新连接并执行真实查询；
- `/api/ready` 返回就绪，Schema 为 14；
- 定时任务没有被多个节点重复执行；
- MCP/CLI 在开发者模式关闭时被拒绝，启用后遵守权限和查询行数限制。
