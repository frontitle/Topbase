# Topbase 0.2.5 升级说明

0.2.5 聚焦仪表盘编辑与安全分享、数仓任务可靠性、通知集成、界面语言基础设施，以及产品官网和在线文档。

## 升级前

1. 备份当前应用数据库。
2. 保存现有 `TOPBASE_MASTER_KEY`，升级后必须继续使用同一个值。
3. 记录当前镜像标签或二进制版本，确认具备回滚条件。

使用发布镜像时，可按[备份步骤](../upgrading.md#升级前备份)将 PostgreSQL 导出到仓库外的私有目录。

## 升级

```bash
git fetch --tags
git checkout v0.2.5
```

编辑已有 `.env`，设置 `TOPBASE_VERSION=0.2.5`，保留原密码和主密钥。先执行 `docker compose -f docker-compose.release.yml config --images`，确认包含 `ghcr.io/frontitle/topbase:0.2.5`，再运行：

```bash
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

直接运行二进制的安装，应使用 0.2.5 源码重新构建，并保持原数据目录和环境变量。

## 数据库变更

本版本依次应用 migrations 016–019，Schema 版本为 19：

- 016：补充数仓运行查找结构；
- 017：补充仪表盘子资源索引；
- 018：增加数仓目标占用与恢复信息；
- 019：增加公开分享的有效期和密码摘要字段。

迁移由 Topbase 启动时自动执行。不要编辑已经发布的迁移文件，也不要手工修改 `schema_migrations`。

## 升级后验收

```bash
curl --fail http://127.0.0.1:8101/api/ready
curl --fail http://127.0.0.1:8101/api/version
```

确认：

- `/api/ready` 返回 `status: ready` 和 `schema_version: 19`；
- `/api/version` 返回 `version: 0.2.5`；
- 原有仪表盘和公开链接仍可访问；
- 新建公开链接可配置有效期与访问密码；
- 数仓计划任务可运行并留下可追踪记录。

## 回滚

应用数据库迁移不支持直接向下回滚。需要回滚时，停止 0.2.5 服务，恢复升级前备份，再启动原版本；不要让旧版本直接连接已升级到 Schema 19 的数据库。
