# Topbase 0.2.2

发布日期：2026-08-30

0.2.2 聚焦生产部署的公开地址一致性、运行端口与 TLS 配置，同时完成工作台品牌 Logo 和交互体验更新。

## 升级前必须确认

1. 备份当前应用数据库或完整 SQLite 数据目录，并保留 `TOPBASE_MASTER_KEY`。
2. 如果当前反向代理访问的是旧端口，确认部署后代理上游地址改为 `8101`（Docker 默认）或你设置的 `TOPBASE_HTTP_PORT`。
3. 如果分享、嵌入或 OAuth 使用公网域名，记录现有外部协议、域名和端口，升级后在“管理后台 → 设置 → 域名与 SSL”复核。

## 运行与公开地址变化

- 直接运行二进制时，默认监听 `:80`；可通过 `TOPBASE_PORT` 或 `TOPBASE_ADDR` 覆盖。
- 同时配置 `TOPBASE_TLS_CERT_FILE` 与 `TOPBASE_TLS_KEY_FILE` 时，Topbase 会直接提供 HTTPS；生产环境仍推荐由反向代理或负载均衡终止 TLS。
- Docker Compose 默认发布 `8101:8080`。使用不同宿主机端口时，在 `.env` 中设置 `TOPBASE_HTTP_PORT`。
- 管理员保存的公开协议、域名和端口会用于生成分享、嵌入和 OAuth 回调地址；它不会更改 DNS、反向代理或监听端口。

## 从源码升级

```bash
git fetch --tags
git checkout v0.2.2
make check
make build
```

重新启动服务后确认：

```bash
curl --fail http://localhost:8101/api/ready
curl --fail http://localhost:8101/api/version
```

`/api/version` 应返回 `version: 0.2.2`；应用数据库 Schema 仍为版本 14。

## Docker 升级

```bash
export TOPBASE_VERSION=0.2.2
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

如使用反向代理，请将上游更新为 `http://127.0.0.1:8101`，或替换为 `.env` 中自定义的 `TOPBASE_HTTP_PORT`。

## 验收清单

- 工作台和管理后台侧栏显示新的 Topbase Logo；
- `/api/ready` 返回就绪，`/api/version` 返回 `0.2.2`；
- 公开仪表盘链接、嵌入地址和 OAuth 回调使用管理员配置的外部地址；
- 已有应用数据库可以完成 migration 校验并正常启动；
- Docker 或二进制部署的健康检查与现有分析、仪表盘、数据源连接均正常。
