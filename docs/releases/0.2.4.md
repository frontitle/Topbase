# Topbase 0.2.4

发布日期：2026-08-30

0.2.4 聚焦可视化质感、数据治理、企业账号接入与运行稳定性。它新增地图、数值环比和敏感字段脱敏，完善仪表盘编排与画布级分享，引入 Excel 本地数据集，并为查询、内存、连接池和前端资源加载增加明确的保护边界。

## 升级前必须确认

1. 备份应用数据库或完整 SQLite 数据目录，并保留原 `TOPBASE_MASTER_KEY`。
2. 确认应用数据库账号具有建表权限；本版本会执行 migration 015，新增 `uploaded_tables`。
3. 记录当前容器内存和查询并发配置。Docker 默认限制为 512 MB，Go 托管内存默认 384 MiB。
4. 不要执行 `docker compose down -v`，该命令会删除 Compose 命名卷。

## 兼容性

- 应用数据库 Schema 从 14 升级到 15，可从 0.2.3 直接升级。
- 已有数据源、分析、仪表盘、权限、订阅和加密连接会保留。
- 新的查询结果与单字段字节上限只会截断过大的交互结果，并在响应 `meta` 中标记原因；不会修改源数据库。
- 钉钉和企业微信已具备企业账号配置结构，当前组织目录同步适配器仍以飞书为准。

## Docker 升级

```bash
git fetch --tags
git checkout v0.2.4
export TOPBASE_VERSION=0.2.4
docker compose -f docker-compose.release.yml pull
docker compose -f docker-compose.release.yml up -d
```

如服务器已经为 Topbase 分配更多内存，可在 `.env` 同步调整 `TOPBASE_CONTAINER_MEMORY_LIMIT` 与 `TOPBASE_GOMEMLIMIT`。建议 Go 软上限保持为容器硬上限的 70%–80%。

## 服务器直接升级

```bash
git fetch --tags
git checkout v0.2.4
make check
make build
```

使用原有应用数据库、数据目录和 `TOPBASE_MASTER_KEY` 重启服务。未设置 `GOMEMLIMIT` 时，Topbase 会使用 512 MiB 的默认 Go 内存保护线。

## 验收清单

- `/api/ready` 返回 `status: ready` 和 `schema_version: 15`；
- `/api/version` 返回 `version: 0.2.4`；
- 原有管理员、数据源、分析和仪表盘在重启后仍然存在；
- 分析和仪表盘可以显示数值、趋势、分类、地图与明细表格，敏感语义字段默认脱敏；
- 仪表盘全屏和分享只作用于画布区域，快速刷新不会重复保留旧请求；
- 管理后台可上传 `.xlsx` 或 `.xlsm` 文件，并在数据模型的“本地数仓”中查看字段；
- 管理后台可维护企业账号平台，并且不会在读取接口中返回已保存的 Client Secret；
- gzip 响应、查询截断提示和运行时内存监控工作正常。
