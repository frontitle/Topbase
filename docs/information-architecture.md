# Topbase 信息架构与数据命名

本文约束用户可见的一级导航、分析分组和数据生命周期命名。代码与 API 可以保留稳定的 `collections`、`warehouse` 等内部名称，但界面必须用业务用户能够理解的语言。

## 一级导航

顺序固定为：

1. 首页
2. 分析
3. 仪表盘
4. 源数据
5. 数据沉淀
6. 回收站

“分析分组”不是一级产品模块，而是分析页面中的整理方式。旧 `/collections/` 入口跳转到 `/questions/?view=groups`，分组详情路由继续保留，以兼容已有链接和权限模型。

## 数据生命周期

```text
源数据（远程、实时、只读）
  → 分析（筛选、关联、汇总、可视化）
  → 数据沉淀（本地保存、按计划更新）
  → 仪表盘（持续观测、分享）
```

### 源数据

原界面名称：“数据浏览”。

- 数据位置：用户连接的远程数据库。
- 更新方式：每次查询直接读取源库当前内容。
- 默认权限：只读，不修改源数据库。
- 适用任务：即时查询、探索明细、创建分析。
- 页面固定提示：“实时 · 只读”。

“数据源”专用于管理后台的连接配置；工作台中的数据消费入口统一称为“源数据”，避免把连接配置和实际数据浏览混在一起。

### 数据沉淀

原界面名称：“数仓”。页面可在说明中注明其技术属性是 Topbase 管理的本地数仓，但一级导航不用技术缩写。

- 数据位置：Topbase 管理的本地存储。
- 更新方式：由分析按计划重新计算并保存，可采用全量替换或增量更新。
- 适用任务：历史追踪、周期对比、稳定指标、结果复用。
- 页面固定提示：“本地保存 · 按计划更新”。

用户动作使用“沉淀”“更新计划”“立即更新”；技术日志和开发文档可以继续使用“物化”“调度”“watermark”。

## 分析与分组

- “分析”是一级内容入口，包含可视化分析和 SQL 分析。
- “分析分组”只承担整理、层级和协作权限，不代表一种新的数据。
- 分析页面提供“分析列表 / 分组管理”两个页签。
- 用户文案使用“个人分组”“团队分组”“移动到分组”；内部领域模型继续使用 `Collection`。
- 仪表盘编辑器按“分组”筛选可添加的分析，但分组本身不再占用一级导航。

## 文案检查

- 不使用“数据浏览”表示工作台入口，改用“源数据”。
- 不使用“数仓”作为非技术用户唯一可见的名称，改用“数据沉淀”，并在帮助文案解释本地数仓能力。
- 不把“数据源”同时用于管理连接和查看业务数据。
- 不把“数据组”作为一级入口；需要表达权限与整理时使用“分析分组”。
