# 用可视化查询创建分析

每个渠道贡献了多少已支付销售额？用可视化查询筛选订单、核对总额并按渠道拆分，最后把结果保存为可重复运行的分析。以下操作使用[入门指南](getting-started.html)里的六行订单示例。

## 按渠道计算已支付销售额

1. 打开 **源数据**，选择示例数据库，再点击 `orders` 表。如果编辑器已收起，点击 **展开查询编辑器**，再选择 **可视化查询**。下方可以看到逐笔订单。
2. 在 **筛选** 中添加 `status` 条件，选择等于，勾选或输入 `paid`。在 **汇总 → 计算** 中选 **求和**，字段选 `amount`，**分组** 暂时留空。点击 **运行并预览**，应得到总额 **680**。
3. 将 **分组** 改为 `channel`。打开 **排序**，选择汇总结果 `sum`，方向选 **降序**。再次运行，现在每一行代表一个渠道。

| 渠道 | 已支付订单金额之和 |
| --- | ---: |
| Web | 300 |
| Partner | 200 |
| Store | 180 |

4. 点击 **保存分析**，命名为「Sales by channel」，选择可写入的分组并确认。保存后会打开分析详情。以后可通过 **编辑** 修改查询。每次改好可视化步骤后，先运行，再保存，才能把最新查询写入分析。

## 决定每行结果代表什么

| 要回答的问题 | 计算方式 | 分组 |
| --- | --- | --- |
| 哪些订单已支付？ | 选「不汇总」，在 **数据** 中勾选要显示的字段 | 留空 |
| 共有多少笔已支付订单？ | 保留已支付筛选，选「记录数」，示例返回 5 | 留空 |
| 有几个渠道产生了已支付订单？ | 对 `channel` 做「去重计数」，示例返回 3 | 留空 |
| 销售额随时间如何变化？ | 保留已支付筛选，对 `amount` 求和 | 选日期类型的 `order_date`，再选日、周、月、季度或年 |

「平均值」「最小值」「最大值」也需要指定字段。**行数限制** 控制返回的结果行数，可设为 1 到 10,000，默认 1,000。若只需前两名，保持按金额降序，并将上限设为 2。核对全渠道总额时，先调高上限，让所有渠道都能返回。

## 关联一张对照表

假设数据库中另有一张 `channels` 表，每个渠道一行，并带有负责人字段 `owner`。打开 **关联数据**，选择 `channels`，用当前表的 `channel` 匹配关联表的 `channel`。选 **保留当前表全部记录**，未匹配到负责人的订单也会保留；选 **只保留匹配记录**，只返回两侧都能匹配的订单。在 **显示关联表字段** 勾选 `owner`，选择 **不汇总** 并运行，可以逐笔检查匹配情况。已在数据模型中设置的外键可以触发自动预选。

如果关联后同一订单号重复出现，检查对照表中渠道键是否唯一。同一个渠道匹配到两行负责人记录，会让同一笔订单出现两次，进而抬高销售总额。

## 给每笔订单计算新字段

选择 **不汇总**，打开 **自定义字段**。新字段名填 `amount_cents`，左侧字段选 `amount`，运算选 **乘**，右侧输入常量 `100`。运行后，每笔订单旁会多出以分为单位的金额。还可以选择加、减、除或拼接，并在右侧使用另一个字段。要在同一条查询中汇总计算后的值，见 [SQL 分析](sql.html)。

将刚保存的渠道销售额制作成图表，见[选择与配置图表](charts.html)。
