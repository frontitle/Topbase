# 配置工作区、访问地址和应用数据

首次启动由第一位管理员创建工作区。管理员随后可在「管理后台 → 设置」中维护工作区名称、时区、对外地址与分享策略，团队成员登录的实例会使用这些设置。

## 创建工作区并设置时区

1. 新安装后，用浏览器打开 Topbase 地址。初始化页会显示当前使用的应用数据库。先确认存储能够在服务重启后保留。容器使用本地存储时，检查部署是否已挂载数据目录。
2. 填写工作区名称、管理员姓名、登录邮箱及至少八位的密码，点击「创建工作区」。已有工作区可用管理员分配的账号登录。
3. 进入「管理后台 → 设置 → 工作区」，将名称设成便于辨认的「销售报表中心」，选择默认时区，点击「保存更改」。已有任务及[数仓定时沉淀](warehouse.html)的执行时区，可在对应计划的列表中核对。

## 生成同事可以打开的链接

假设同事通过反向代理访问 `https://bi.example.com:8443`。在「访问与安全」填写下列三项，检查「生成地址」后再保存。

| 配置项 | 示例值 | 含义 |
| --- | --- | --- |
| 访问协议 | HTTPS | 同事在浏览器中使用的协议，也可以选择自动识别。 |
| 自定义域名 | `bi.example.com` | 只填主机名，端口填在单独的输入框。 |
| 外部端口 | `8443` | 用于生成链接；留空时使用协议默认端口，例如 HTTPS 的 443。 |

打开已有仪表盘的「分享」，核对生成的主机名。DNS、证书、反向代理路由、Docker 端口映射和进程监听由部署环境配置。如果生成地址正确但无法访问，从读者所在网络检查这些配置。

## 管理对外访问

在「访问与安全」中，「允许公开链接」使已发布的仪表盘可免登录访问；「允许嵌入到外部页面」使已经公开的仪表盘可以在 iframe 中展示。保存后，可到「管理后台 → 嵌入与公开链接」查看涉及的内容。关闭公开链接会同时停用已有公开访问和嵌入。按[分享指南](sharing.html)验证读者能否访问。

## 检查或备份应用数据

进入「应用数据」，查看当前引擎和存储状态。这里保存工作区账号、连接、分析、仪表盘和计划任务。点击「导出备份」可下载逻辑备份，文件含密码哈希和加密后的连接信息，应妥善保存。业务源数据库需单独备份。

使用 SQLite 应用库且出现「迁移到生产环境」时，先导出备份，准备专供 Topbase 使用的空 PostgreSQL 或 MySQL 数据库。填写主机、端口、库名、账号和 TLS 模式。PostgreSQL 还需填写 schema。确认目标为空后再开始这项一次性复制。成功后核对报告中的行数和表数，按结果提示更新部署的应用数据库配置并重启。重新打开「应用数据」，核对活动引擎，再打开一张已知仪表盘。
